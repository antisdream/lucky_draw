# lucky_draw 1.1 검증 기록

검증일: 2026-09-09 (한국 시간). 기준: `30f92cf` 이후 로컬 변경. 이번 작업의 웹 배포·Git push는 수행하지 않았다.

## 구현 범위

- 다트: 원판 회전 → 마우스/터치로 핀을 위로 끌어 놓기 → 방향에 따른 비행 → 명중 시 추첨. 짧은 탭·아래 방향은 투척으로 처리하지 않고, 빗나감은 결과 없이 재시도한다.
- 냠냠 마지막 쿠키: 몬스터가 접시의 쿠키를 먹으며 마지막 쿠키의 주인공을 공개한다.
- 꼬리 뽑는 우체통: 다섯 꼬리 중 하나를 잡아 아래로 당기면 편지를 공개한다.
- 당첨은 기존의 전체 후보 무작위 추첨을 유지한다. 방향·타이밍·꼬리 색이 당첨 확률을 높이지 않는다. 원판의 숫자와 소품 개수가 후보 번호·인원이라는 오해를 막는 안내를 표시한다.
- APK에는 HTML을 포함하고 인터넷 권한을 요청하지 않는다. Android 파일 선택·저장 창으로 CSV/HTML을 가져오거나 내보낸다. 앱 자체의 자동 저장은 하지 않으며 기존의 명시적 기기 저장 버튼을 사용한다.

## 로컬 자동 검증과 실제 브라우저

`npm test`: 54개 통과. 추첨의 중복/회차, 큰 정수, CSV와 HTML 보호, 저장 데이터 복원, 기존 오프라인 로직, 다트 명중/빗나감/취소, 꼬리 당기기 기준을 포함한다.

`npm run build`: 독립 HTML 생성과 인라인 스크립트 구문 검사 통과. 웹 의존성은 추가하지 않았다.

Chromium의 `http://localhost:4178`에서 다음을 실제 조작했다. 4177은 앞선 시험의 서비스 워커 캐시가 남아 있어 새 코드의 확인에는 사용하지 않았다.

| 시나리오 | 관찰 |
| --- | --- |
| 다트 마우스 드래그 | 회전 중 핀을 원판으로 끌어 놓자 비행하고 결과 공개 |
| 다트 빗나감 → 재시도 | 원판 밖으로 던지면 결과 영역은 숨김 유지, 같은 판에서 다시 명중시키면 결과 공개 |
| 꼬리 마우스 드래그 | 두 번째 꼬리를 아래로 당기자 편지 연출과 결과 공개 |
| 꼬리 키보드 대체 조작 | 조작 화면에서 Enter를 누르면 가운데 꼬리로 진행하고 결과 공개 |
| 룰렛·쿠키 | 각각 3회×2명, 6명 결과의 중복 없음과 회차 표시 확인 |
| 다트 다중 결과 | 3회×2명 결과와 중복 없음 확인 |
| 시작 후 화면 위치 | 작은 화면에서 시작 버튼을 누르면 원판·꼬리 조작 영역이 화면에 표시됨 |
| 브라우저 오류 | 관찰한 조작 동안 오류 로그 없음 |

현재 브라우저의 HTML 다운로드 UI와 다운로드 동작 호출은 확인했지만, 이번 실행에서 Windows 다운로드 폴더에 새 파일이 생긴 것은 확인하지 못했다. 이 항목을 새 버전의 실제 파일 저장 성공으로 계산하지 않는다. 기존 1.0 파일 저장 검증은 별도 기록이다.

## Android 빌드와 검사

- 패키지: `com.antisdream.luckydraw`, 버전 `1.1.0-test` / versionCode 1.
- Java 소스 17, Gradle 9.5.0, AGP 9.3.0, compile/target SDK 36, min SDK 26.
- AndroidX WebKit 1.17.0, Activity 1.13.0. 빌드 시 필요한 의존성을 최초로 내려받으며 앱 실행 시에는 사용하지 않는다.
- `.\scripts\build-android.ps1 -Offline -Check`로 2026-09-09 18:35에 화면 여백 수정 후 최종 오프라인 빌드가 29초 내 완료됐다. `assembleDebug`, `lintDebug` 통과. lint는 오류 0개, 경고 3개: target/compile SDK 37 권고와 Gradle 9.7.1 권고. 이번 Android 16 테스트의 빌드 버전을 유지했으며 최신 Android 전체 호환성으로 확대하지 않는다.
- JavaScript는 앱에 포함된 게임에 필요하다. WebView의 탐색은 자체 asset URL로 제한하며 외부 요청을 차단한다. 가져온 HTML은 데이터만 해석한다.
- Android 파일 내보내기는 자체 origin의 main frame에서 지정된 HTML/CSV 파일만 처리하는 메시지 경로를 사용한다.
- 뒤로가기는 AndroidX dispatcher를 사용한다. WebView 렌더러 중단 시 명시적 재실행 안내를 표시한다. 이 복구 분기의 실제 장애 주입 검증은 하지 않았다.

## 실제 기기

Z Flip4 `SM-F721N`, Android 16, 화면 1080×2640, density 480, Android System WebView 151.0.7922.199에서 ADB 설치와 터치 입력을 사용했다. 사용자가 ADB 방식을 명시적으로 허용한 뒤 진행했으며 기존에 같은 패키지의 앱은 없었다.

앱을 처음 실행했을 때 WebView에 직접 준 여백이 콘텐츠를 상태 표시줄·내비게이션 바와 분리하지 못했다. 여백을 바깥 FrameLayout에 적용하도록 수정했다. 최종 APK를 덮어 설치하고 WebView 영역 `[0,94]–[1080,2496]`, 상태 표시줄 글자, 숫자 키보드가 열린 입력 화면을 확인했다. 최종 APK 설치와 앱 시작이 성공했으며 기기에 설치된 `base.apk`의 SHA-256이 위 최종 산출물과 일치했다.

| 시나리오 | 실제 관찰과 판정 |
| --- | --- |
| 다트 빗나감 → 명중 | 최종 APK에서 원판 밖으로 터치 드래그하면 재시도 안내만 표시되고 결과는 생성되지 않음. 같은 판에서 다시 원판으로 던지면 3회×2명 결과 6개가 중복 없이 공개됨 |
| 꼬리 짧은 당김 → 충분한 당김 | 최종 APK에서 짧게 당기면 추가 조작 안내, 아래로 길게 당기면 결과 `11` 공개 |
| CSV 가져오기 | Android 파일 선택 창에서 테스트 CSV를 선택하고 `이름` 열을 지정. 한글·쉼표 포함 이름·공백·영문을 포함한 후보 6명 확인 |
| 쿠키 다중 추첨 | 최종 APK에서 3회×2명. 김하늘, `별, 하나`, 박별, Team Lucky, 우리 팀 A, 이바다가 중복 없이 표시됨 |
| CSV 저장 | Android 저장 창으로 Download에 저장 후 실제 156 bytes 파일 확인. UTF-8 BOM, 헤더, 다트 결과 `5`와 후보 ID `n:4` 확인. 화면 여백 수정 전 APK에서 수행 |
| HTML 저장 | 최종 APK에서 Android 저장 창을 사용. 실제 109,618 bytes 파일의 후보 6명, CSV 모드, 3회×2명 설정, 쿠키 결과 6개와 게임 코드 포함 확인 |
| HTML 데이터 불러오기 | 이 앱만 강제 종료 후 다시 열고 Android 파일 선택 창으로 저장 HTML을 선택. 후보 6명과 3회×2명 설정을 화면에서 확인하고 해당 데이터로 룰렛·다트 후속 추첨 성공 |
| Android 뒤로가기 | 최종 APK에서 결과 화면 → 홈 복귀 확인 |
| 이 기기에 저장 → 재실행 유지 | 복원된 후보·설정을 화면에서 확인한 후 저장 버튼 클릭과 완료 문구 확인. 이 앱만 강제 종료·재실행한 뒤 CSV 후보 6명, 인원 2·회차 3, 기존 쿠키 결과 6개와 순서가 유지됨 |
| 최종 APK 룰렛 추첨 | 복원한 CSV 후보로 3회×2명 실행. 후보 6명 모두 중복 없이 결과에 표시됨 |
| 앱 오류 기록 | 최종 재실행 프로세스의 앱 로그에서 FATAL EXCEPTION, Uncaught, ANR, ERROR:CONSOLE 일치 항목 0개. 이전 모든 프로세스·장시간 실행의 무오류를 뜻하지 않음 |

시험 도중 USB 연결이 끊겼으나 다시 연결된 뒤 남은 저장 유지·룰렛·다트·설치 파일 대조 검사를 완료했다. 이 기록은 ADB로 입력한 범위의 동작 확인이며 손가락 조작감·전체 기기 호환성 검증은 아니다. 마지막에는 앱의 게임 선택 홈 화면을 열어 두었다.

다른 앱, 휴대전화의 네트워크·회전 설정, ADB 포트 연결은 변경하지 않았다. 앱 자체의 강제 종료·재실행만 사용했다. 휴대전화 Download에 작업용으로 만든 `lucky-draw-candidates-qa.csv`, `lucky-draw-qa-20260909.csv`, `lucky-draw-qa-20260909.html`을 남겼으며 기존 파일은 변경하지 않았다.

## 검증 경계

PC의 `file://` 직접 실행, iPhone/Safari, 배포 주소의 PWA 오프라인 준비, 실제 기기의 접힘·가로 화면과 장시간 사용은 이번 검증에 포함하지 않는다. APK는 인터넷 권한 없이 내장 HTML을 실행했고 PC 개발 서버도 종료한 상태였다. 휴대전화의 네트워크를 끄는 별도 시험은 하지 않았다. APK 실행과 배포 웹 주소의 오프라인 지원은 별개다. 현재 웹 주소에 새 게임이 배포됐다는 의미가 아니다.
