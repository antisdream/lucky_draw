# lucky_draw 검증 기록

검증일: 2026-09-08 (한국 시간)

## 확인한 내용

- `npm test`: 32개 테스트 통과.
- `npm run build`: 단일 `index.html` 생성 성공. CSS, JavaScript, 초기 데이터 포함.
- `node --check`: 앱과 핵심 로직의 JavaScript 문법 검사 통과.
- `http://localhost:4177`: 로컬 서버 HTTP 200 확인.
- 외부 런타임 자산, 네트워크 요청 코드, 입력의 `maxlength` 없음.
- HTML 요소의 고정 ID와 JavaScript 참조의 연결 확인.

## 추첨 규칙

- 후보 1명, 중복 허용 반복 선정, 후보보다 많은 선정 요청의 사전 차단.
- 1,000개 전체 선정 시 중복과 누락 없음.
- 후보 3개의 가능한 선택 경로 6개가 서로 다른 모든 순열에 일대일로 대응.
- 10의 100제곱 크기 번호 범위를 전체 배열 생성 없이 처리.
- 안전한 정수 범위를 넘는 번호의 정밀도 보존.
- 범위 밖 난수 재추첨, Web Crypto 사용 불가 상태 처리.
- 같은 이름의 서로 다른 후보 ID 유지.

## 입력 및 저장 형식

- CSV BOM, CRLF, 쉼표, 큰따옴표 이스케이프, 여러 줄 셀, 제목 유무, 빈 셀, 누락 열.
- TSV와 세미콜론 구분 파일 감지.
- 깨진 따옴표 입력의 명시적 오류.
- HTML 데이터의 종료 태그 삽입 방어와 직렬화 왕복 보존.
- CSV 수식 실행 문자 보호.

## 추첨 흐름

실제 앱의 추첨 컨트롤러를 최소 화면 어댑터와 함께 실행했습니다. 아래 결과는 브라우저 조작 E2E 결과와 구분합니다.

- 네 게임 각각 3회 × 2명 선정 및 회차 정보 확인.
- 중복 시작 방지, 바로 결과 보기의 기존 선정 결과 유지.
- 대량 결과 계산 중 취소 시 부분 결과를 완료로 표시하지 않음.
- 취소 후 재시작 시 이전 애니메이션 프레임이 새 추첨을 완료시키지 않음.

## 확인 범위의 한계

- 실제 브라우저의 화면 배치·애니메이션 육안 검증, 모바일 실기기, 파일 다운로드 후 다시 열기는 이 기록의 검증 범위에 포함하지 않습니다.
- 인원에 고정 상한은 없지만 물리적인 무한 크기는 처리할 수 없습니다. 직접 입력·CSV·선정 결과는 기기 메모리를 사용합니다.
- 결과 수가 아주 많으면 난수 생성·명단 처리 시간이 연출 시간을 넘을 수 있습니다.
- 통계적 대규모 난수 인증이나 제3자 감사는 수행하지 않았습니다.
- 호스팅의 접근 권한과 오프라인 HTML 전달은 서로 다른 배포 방식입니다. HTML 자체는 서버 인증을 요구하지 않습니다.
