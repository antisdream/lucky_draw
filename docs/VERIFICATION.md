# lucky_draw 검증 기록

검증일: 2026-09-08~09 (한국 시간)

## 판정과 범위

자동 테스트 46개와 실제 Chromium 브라우저의 네 게임 추첨 흐름을 확인했습니다. 서버를 종료한 뒤 웹앱을 다시 열어 추첨하고 저장한 HTML의 데이터를 가져오는 오프라인 흐름도 통과했습니다.

PC의 `file://` 직접 열기와 iPhone·Android 실기기를 모두 통과했다는 판정은 아닙니다. 브라우저 도구가 로컬 파일 URL 탐색을 제한하여 실제 다운로드 파일과 동일한 바이트를 localhost HTTP로 제공해 재실행했습니다. 휴대전화 검증은 Chromium 화면 크기 390×844에서 진행했으며 Safari 엔진이나 홈 화면 설치 자체를 확인하지 않았습니다.

## 자동 검증

- `npm test`: 46개 테스트 통과.
- `npm run build`: 루트와 `dist/`의 `index.html` 생성 성공. 게임의 CSS·JavaScript·초기 데이터 포함.
- 독립 HTML에 외부 실행 스크립트·스타일·모듈 가져오기 없음. 호스팅 보조 파일은 웹앱 오프라인 준비를 선택했을 때만 사용.
- HTML 고정 ID와 JavaScript 참조의 연결, 입력의 고정 글자 수 제한 부재 확인.
- 서비스 워커의 캐시 후 오프라인 실행, 로그인 화면 캐시 거부, 다른 경로 제외, 범위에 맞는 이전 앱 캐시 정리 확인.
- 기능 미지원 또는 시작 오류가 발생했을 때 실행 안내를 유지하고 준비 완료로 덮어쓰지 않는 동작 확인.
- 저장 데이터의 형식·후보·결과 수 검증, 기존 버전 복원, 손상된 입력 거부, 가져온 HTML의 JSON만 읽는 동작 확인.

## 실제 브라우저에서 확인한 사용자 흐름

| 항목 | 조작과 관찰 결과 |
| --- | --- |
| 첫 실행 | 게임 선택 화면과 네 게임 메뉴가 표시되고 정적 실행 안내가 숨겨짐. 데스크톱 화면을 육안 확인함. |
| 룰렛 | 일반 번호로 3회×2명 추첨. 후보 한 명에 안전한 정수 범위를 넘는 시작 번호 `90071992547409930000000000000001`을 사용해 정확한 전체 번호 결과도 확인함. |
| 다트 | 후보 12명에서 3회×2명 추첨 후 여섯 명의 중복 없는 결과 확인. |
| 냠냠 레이스 | 한글, 쉼표, 동명이인 두 명, HTML 종료 태그 형태의 문자열, 이모지를 포함한 직접 입력 후보 여섯 명을 3회×2명 추첨. 모든 후보가 별도 항목으로 표시되고 입력을 스크립트로 실행하지 않음. |
| 꼬리잡기 | 실제 파일 선택 창으로 `examples/candidates.csv`를 불러와 이름 열을 선택하고 2회×3명 추첨. CSV의 여섯 이름과 회차가 정상 표시됨. |
| HTML 저장 | 브라우저 다운로드 폴더에 실제 HTML 파일이 생성됨을 파일 메타데이터와 내용으로 확인. 이름·후보·설정·선정 순서가 저장 데이터와 일치함. |
| 저장 HTML 재실행 | 다운로드한 파일을 바꾸지 않고 `/qa/restored.html`로 제공. 저장한 여섯 후보, 게임, 설정, 결과를 복원하고 새 추첨도 완료. `file://` 실행 검증과는 구분함. |
| 스크립트 차단 | JavaScript를 허용하지 않는 sandbox iframe에서 실행 안내와 브라우저 링크가 표시되고 게임 조작 화면은 숨겨짐. 브라우저의 보안 설정은 변경하지 않음. |
| 모바일 배치 | 390×844 크기의 Chromium에서 후보 입력·설정·추첨·결과·도움말 조작. 문서 너비가 화면의 사용 가능한 너비를 넘지 않음. |
| 기기 저장 | 웹앱에서 CSV 후보·설정·결과를 직접 저장하고 새로 열어 복원함. |
| 오프라인 재실행 | 도움말에서 오프라인 준비 후 로컬 서버를 실제 종료. 별도의 HTTP 요청으로 서버 접속 불가를 확인한 뒤 같은 브라우저에서 루트 주소를 다시 열어 꼬리잡기 추첨을 완료함. 최종 캐시 우선 구현에서도 다시 확인함. |
| 오프라인 파일 불러오기 | 서버가 꺼진 상태에서 실제 파일 선택 창으로 저장한 HTML을 읽어 직접 입력 후보와 냠냠 레이스 결과를 복원함. |
| 브라우저 오류 | 확인한 추첨·저장·복원·오프라인 흐름에서 콘솔 오류 없음. |

## 추첨 규칙과 데이터 검증

- 후보 1명, 중복 허용 반복 선정, 후보보다 많은 선정 요청의 사전 차단.
- 1,000개 전체 선정 시 중복과 누락 없음.
- 후보 3개의 가능한 선택 경로 6개가 서로 다른 모든 순열에 일대일로 대응.
- 10의 100제곱 크기 번호 범위를 전체 배열 생성 없이 처리.
- 안전한 정수 범위를 넘는 번호의 정밀도 보존.
- 범위 밖 난수 재추첨과 Web Crypto 사용 불가 상태 처리.
- 같은 이름의 서로 다른 후보 ID 유지.
- CSV의 BOM, CRLF, 쉼표, 큰따옴표, 여러 줄 셀, 제목 유무, 빈 셀, 누락 열, TSV·세미콜론 구분과 잘못된 따옴표 처리.
- HTML 데이터의 종료 태그 삽입 방어와 직렬화 왕복 보존, CSV 수식 실행 문자 보호.

## 컨트롤러 수준에서 확인한 흐름

다음 항목은 실제 앱 컨트롤러와 최소 화면 어댑터를 함께 실행한 자동 검증이며, 별도의 브라우저 조작 결과로 확대하지 않습니다.

- 네 게임 각각 3회×2명 선정과 회차 정보.
- 중복 시작 방지, 바로 결과 보기의 기존 선정 결과 유지.
- 대량 결과 계산 중 취소 시 부분 결과를 완료로 표시하지 않음.
- 취소 후 재시작 시 이전 애니메이션 프레임이 새 추첨을 완료시키지 않음.

## 남은 확인과 사용 조건

- 사용자가 원래 HTML을 열었던 앱과 브라우저 설정은 확인되지 않았습니다. 원본 문구가 `noscript` 안에 있었던 점은 확인했지만, 실제 기기에서 어느 제한이 적용됐는지는 단정하지 않습니다.
- HTML 파일은 코드를 포함할 수 있지만 JavaScript 실행을 막는 파일 미리보기의 제한을 해제할 수 없습니다. PC 파일은 지원 브라우저로, 모바일은 최초 온라인 준비가 가능한 웹앱 경로로 사용하도록 안내합니다.
- 실제 iPhone·Android, 각 브라우저의 파일 연결·다운로드·공유 메뉴, 홈 화면 설치와 설치 후 저장소 유지 여부는 추가 확인이 필요합니다. 사용할 홈 화면 앱에서도 오프라인 준비와 후보 저장을 하고 인터넷을 끊어 확인하도록 README에 안내했습니다.
- 오프라인 앱 파일과 기기 저장 데이터는 서로 다른 저장입니다. 시크릿 모드·저장 공간 정리·브라우저 데이터 삭제로 사라질 수 있습니다. 설정 변경은 자동 저장하지 않습니다.
- 로컬 오프라인 성공은 호스팅 인증·캐시와 모든 브라우저의 장기 보존을 입증하지 않습니다. 웹 버전의 첫 접속과 오프라인 준비에는 인터넷과 소유자 접근 권한이 필요합니다.
- 인원에 고정 상한은 없지만 기기 메모리는 유한합니다. 직접 입력·CSV·대량 결과는 메모리를 사용하며, 결과 수가 아주 많으면 연출 시간보다 계산이 오래 걸릴 수 있습니다.
- 통계적 대규모 난수 인증이나 제3자 감사는 수행하지 않았습니다.
