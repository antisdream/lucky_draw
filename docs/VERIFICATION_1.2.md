# 1.2.0 검증 기록 — 애니메이션 선택, 오프라인 APK, 서명 및 GitHub 링크

검증일: 2026-09-09 · 로컬 HTML 및 Z Flip4(SM-F721N, Android 16) · ADB 설치·터치 입력과 화면 촬영 사용.

## 요청과 반영 범위

| 항목 | 반영 결과 |
| --- | --- |
| APK에서 움직임 없이 바로 결과가 나오는 현상 | 기기 설정 따르기 / 전체 애니메이션 / 간결한 움직임을 분리. 전체 선택은 운영체제의 움직임 줄이기와 독립적으로 동작 |
| 데이터·Wi-Fi 없는 APK 실행 | 게임을 APK에 포함하고 INTERNET 권한을 요청하지 않는 구조 유지. 네트워크가 없는 실제 기기에서 재실행과 네 게임 검증 |
| HTML·APK 변경 난도 높이기 | HTML JavaScript 압축·식별자 축약, Release APK 서명, 앱·WebView 디버깅 비활성화, R8 코드·리소스 최적화 |
| 푸터 변경 | 기존 문구를 GitHub · antisdream 링크로 교체. APK는 해당 프로필만 외부 브라우저로 연결 |

다른 프로젝트의 코드·앱은 변경하지 않았다. 기존 테스트 APK는 사용자가 교체 설치와 백업 복원을 승인한 뒤 럭키드로우 패키지만 삭제·재설치했다. 이 문서는 GitHub 게시와 Sites 재배포 전에 마친 로컬 구현·실기기 검증의 기록이다. 이후 게시·재배포 결과는 해당 Git 커밋과 Sites 배포 기록으로 확인한다.

## 애니메이션 원인과 검증

기존 코드는 앱의 간결한 움직임 설정과 `prefers-reduced-motion`을 OR로 합쳤다. 기기 설정이 참이면 앱 버튼으로 전체 연출을 선택할 수 없었으며, 연출 시간이 160ms가 되고 중간 프레임을 그리지 않았다. 기기에서 `animator_duration_scale`, `transition_animation_scale`, `window_animation_scale`이 모두 `0`인 것을 확인했다. 1.1 검증은 조작·결과·저장 경로 중심이었으며 이 중간 연출 문제를 검출하지 못했다.

1.2에서는 기본값으로 기기 설정을 따르되, 사용자가 전체 애니메이션을 명시하면 JavaScript와 CSS 모두 전체 연출을 사용한다. 선택은 후보·결과 저장과 별도로 기억하며 HTML에도 포함한다. 이전 HTML의 `reduced` 값도 읽을 수 있다. 휴대전화의 애니메이션 설정은 변경하지 않았다.

- 컨트롤러 테스트: 네 게임에서 운영체제 움직임 줄이기가 켜져 있어도 전체 모드의 중간 프레임과 선택한 시간 유지. 1.8초·3.4초·5초 시간 분기, 기기 설정/간결 모드의 짧은 연출, 이전 저장 호환과 선호도 재실행 복원 확인.
- Chromium 로컬 브라우저: 최적화된 HTML에서 네 게임의 중간 진행 상태와 결과, 다트·꼬리 대체 버튼 조작 확인. 간결 모드 선택과 조작 대기 확인.
- 새 움직임 메뉴를 포함한 320px·431px·800px 브라우저 화면에서 문서 가로 넘침이 없었다. 임시 화면 크기 설정을 복구했으며 브라우저 경고·오류 로그는 없었다.
- Z Flip4: 실제 선택 화면에서 기기 설정에 따른 간결 모드 안내를 확인한 뒤 전체 애니메이션으로 변경. 3.4초 설정에서 네 게임의 중간 화면을 두 시점에 촬영하고, 7초 녹화 파일과 최종 결과를 확보했다. 룰렛 회전각, 다트 위치와 원판 각도, 남은 쿠키 수, 꼬리 길이와 편지 개방 상태가 시간에 따라 달라졌다. 네 게임 모두 CSV 후보 6명을 2명씩 3회 중복 없이 선정했다.
- 촬영 시점은 입력 명령 시작 후 약 1.5~3.0초다. ADB 및 화면 캡처 지연이 포함되므로 정확한 프레임률이나 터치 반응 지연 측정으로 해석하지 않는다. 실기기의 세 시간 옵션 전체를 각각 계측한 것은 아니다.

## 실제 오프라인 실행

1. 실행 전 Wi-Fi·모바일 데이터 설정과 애니메이션 설정을 기록했다.
2. Wi-Fi를 끄고 데이터 비활성화 명령을 실행했다. 이 기기는 SIM 상태가 `ABSENT,NOT_READY`이므로 데이터 설정의 숫자는 `1`로 남았지만 두 셀룰러 연결 상태는 모두 `0`이었다.
3. 시스템의 `Active default network: none`을 확인했다. 이 검증은 데이터 토글 숫자만으로 오프라인을 판정하지 않는다.
4. 럭키드로우만 강제 종료한 뒤 새 프로세스로 실행했다. 콜드 스타트 결과는 정상이며 기록된 TotalTime은 247ms였다.
5. 룰렛·다트·쿠키·꼬리 게임의 조작, 중간 연출, 각 6명 결과를 확인했다.
6. `finally` 정리에서 연결 설정을 복원했다. 전후 Wi-Fi·데이터·비행기 모드·세 애니메이션 설정 값이 동일함을 확인했다. 이후 GitHub 프로필도 온라인으로 열렸다.

통신사 SIM이 연결된 상태에서 데이터 토글을 끄는 별도 실험이나 비행기 모드 전환은 수행하지 않았다. 이번 기기의 실제 네트워크 부재 상태에서 APK 실행이 통과했다는 근거다.

## APK 보호 조치와 한계

| 검사 | 결과 |
| --- | --- |
| APK manifest | 패키지 `com.antisdream.luckydraw`, versionCode 2, versionName 1.2.0, minSdk 26, targetSdk 36. debuggable 속성 없음(기본 false), INTERNET 권한 없음 |
| WebView 디버깅 | 최종 DEX의 `setWebContentsDebuggingEnabled` 인자가 0임을 확인. 실행 중 해당 앱 PID의 WebView 디버그 소켓 없음 |
| 앱 디버깅 | 실제 기기의 `run-as` 검사에서 `package not debuggable`로 거부됨. 우회 시도 없음 |
| 최적화 | R8 실행 완료와 매핑 생성 확인. 매핑은 빌드 출력에만 보관하며 APK에 포함하지 않음 |
| 서명 | apksigner 검증 통과, APK Signature Scheme v2, RSA 3072-bit. 전용 Release 인증서 사용 |
| HTML | 외부 실행 자산·소스맵 없이 JavaScript 압축 및 식별자 축약. APK 내부 HTML과 최종 index.html 바이트 일치 |

서명 인증서 SHA-256: `c8f4129a7787be70d63369db443933b8ccc6ce1766bafe8526983e7cedcf5c75`.

서명 키는 로컬 `.signing/`에서 재사용하며 Git에서 제외한다. 암호 저장은 Windows 현재 사용자 DPAPI와 폴더 ACL을 사용한다. 공개 인증서 지문은 비밀 키가 아니다. 다른 PC로의 서명 키 이전·복구는 이번 검증 범위가 아니다.

**HTML 개발자 도구·파일 수정과 APK 역공학을 완전히 막지는 못한다.** HTML 코드는 최종 사용자의 컴퓨터에서 실행되고, APK 내부 자산도 추출할 수 있다. F12 차단은 넣지 않았다. 루팅·후킹·재패키징 방지, 서버 서명 결과, 스토어 검증·Play Integrity는 포함하지 않으므로 추첨 결과의 외부 감사나 무결성 보증으로 사용할 수 없다.

## GitHub 링크와 파일 복원

- 푸터 링크 주소는 `https://github.com/antisdream`이다. Android는 메인 프레임에서 사용자가 누른 이 주소만 ACTION_VIEW로 외부 브라우저에 전달한다.
- Z Flip4에서 실제 링크를 눌러 Chrome으로 전환된 것과 주소창의 `github.com/antisdream`, 프로필 표시를 확인했다. 게임 WebView에 인터넷 권한을 추가하지 않았다.
- 교체 전 HTML 백업은 폰 Download에 저장하고 PC로 가져와 데이터 블록을 확인했다.
- 새 APK에서 원본 백업을 불러오고 후보 6명·2명씩 3회 설정을 확인했다. QA 추첨 후 다시 원본을 복원했다.
- 새 APK의 Android 파일 저장 창으로 `lucky-draw-v12-restored-20260909.html`을 저장했다. 실제 파일 90,864바이트의 데이터 블록을 비교해 원래 후보·설정·마지막 결과 전체가 일치하고 `motionMode: full`이 추가된 것을 확인했다.
- 기기에 저장한 뒤 럭키드로우만 강제 종료·재실행했다. 전체 애니메이션, 후보 6명, 2명씩 3회 설정과 원본 결과의 순서가 유지됨을 UI 기록으로 대조했다. 홈 화면으로 돌아가 테스트를 마쳤다.
- 최종 Release의 CSV 저장으로 생성한 실제 파일 516바이트에서 UTF-8 BOM과 원래 결과 6행의 이름·순서 일치를 확인했다.
- 최종 앱 프로세스의 로그에서 FATAL EXCEPTION, Uncaught, ANR, ERROR:CONSOLE 항목을 발견하지 못했다. 이전의 모든 프로세스나 장시간 실행을 포괄한 무오류 보증은 아니다.

## 빌드와 산출물

- `npm test`: **63/63 통과**. 최초 제한 환경의 자식 프로세스 실행 오류 후 허용된 실행 환경에서 재검증했다.
- `scripts/build-android.ps1 -Offline -Check`: **Release 빌드 성공**, lint **오류 0개·경고 2개**. 경고는 targetSdk/compileSdk 최신 버전 권고다. deprecated API 및 JDK 네이티브 접근 안내도 빌드 출력에 남아 있다.
